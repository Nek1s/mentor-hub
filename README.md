# MentorHub

MentorHub — учебный MVP сервиса наставничества. Ученик может просматривать наставников, планировать встречи и сохранять заметки по итогам общения.

Проект выполняется по лабораторным работам курса Fullstack. В первой лабораторной создан интерфейс на React, во второй — backend на FastAPI с PostgreSQL и SQLAlchemy, в третьей — модульная структура frontend, а в четвёртой — аутентификация и авторизация через JWT.

## Возможности

- интерфейс с экранами главной страницы, наставников, расписания, заметок и профиля;
- REST API для наставников, учеников, встреч и заметок;
- CRUD-операции для каждой основной сущности;
- валидация входящих данных с помощью Pydantic;
- проверка связей между сущностями и бизнес-правил;
- интерактивная документация API в Swagger UI;
- PostgreSQL-конфигурация без хранения настоящих секретов в Git.
- регистрация, вход, обновление токенов и выход из учётной записи;
- защита пользовательских данных access token и отзыв refresh-сессии при выходе.

## Архитектура frontend

Начиная с лабораторной работы №3 frontend организуется по упрощённому варианту Feature-Sliced Design. Полная FSD для учебного MVP была бы избыточна, поэтому используются только слои, которые помогают отделить страницы, предметные данные, действия пользователя и общие элементы.

```text
src/
├── app/                   # точка запуска, маршрутизация, тема приложения
├── pages/                 # самостоятельные экраны: главная, наставники, расписание и т. д.
├── features/              # действия пользователя: создание встречи, создание заметки
├── entities/              # данные предметной области: наставники, встречи, заметки, профиль
└── shared/                # переиспользуемые компоненты, типы, константы и утилиты
```

Назначение слоёв:

- `app` объединяет приложение целиком и не содержит предметной логики;
- `pages` собирает конкретный экран из компонентов и функций;
- `features` содержит законченные пользовательские действия и состояние их форм;
- `entities` хранит типы, демонстрационные данные и компоненты, относящиеся к одной сущности;
- `shared` предназначен для кода, который может использоваться в разных частях проекта и не зависит от конкретной сущности.

В этой структуре `App.tsx`, `main.tsx` и `theme.ts` находятся в `app`; демонстрационные данные и типы разнесены по `entities`; общие компоненты находятся в `shared`; страницы остаются в `pages`.

## Лабораторная работа №3

В третьей лабораторной frontend получил модульную структуру и динамическое поведение без подключения к backend.

- состояние наставников, встреч и заметок хранится в типизированном `AppDataProvider` на React Context;
- функции создания встречи и заметки вынесены в `features`;
- формы проверяют обязательные поля и показывают ошибки рядом с ними;
- после создания заметка или встреча сразу появляется на связанном экране;
- для экранов с данными добавлены состояния загрузки, ошибки и пустого списка;
- добавлены небольшие анимации появления записей и переключения заметок.

Данные наставников, встреч и заметок пока остаются демонстрационными и после перезагрузки страницы возвращаются к начальному состоянию. Полная интеграция этих экранов с API FastAPI и PostgreSQL будет выполнена в лабораторной работе №5.

## Лабораторная работа №4

В четвёртой лабораторной добавлена аутентификация и авторизация пользователей.

- пароль сохраняется только как стойкий Argon2-хеш в таблице `users`;
- регистрация создаёт одновременно учётную запись и профиль ученика;
- при регистрации и входе backend выдаёт пару JWT: короткоживущий access token и refresh token;
- каждая refresh-сессия имеет уникальный идентификатор и запись в таблице `refresh_sessions`;
- `POST /auth/refresh` выдаёт новый access token только для действующей, неотозванной сессии;
- `GET /auth/me` получает текущего пользователя по access token;
- ученик может работать только со своим профилем, заметками и встречами;
- frontend хранит токены, восстанавливает сессию после обновления страницы и перенаправляет гостя на страницу входа;
- logout отзывает refresh-сессию на backend и очищает локальное состояние frontend.

## Быстрый запуск backend с PostgreSQL

### 1. Подготовьте PostgreSQL

В системе должен быть установлен и запущен сервер PostgreSQL. Для управления базой можно использовать pgAdmin. Создайте в нём:

- пользователя `mentorhub_user` с правом входа;
- базу данных `mentorhub`, владельцем которой будет `mentorhub_user`.

Подробный порядок действий приведён в [REPORT_LAB_2.md](REPORT_LAB_2.md). Параметры подключения для приложения находятся в `backend/.env.example`.

### 2. Подготовьте Python-окружение

Перейдите в папку backend:

```powershell
cd backend
py -m venv .venv
```

Установите зависимости:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Создайте локальный конфигурационный файл:

```powershell
Copy-Item .env.example .env
```

Файл `.env` не добавляется в Git. Укажите в нём пароль созданного пользователя PostgreSQL вместо `CHANGE_ME`.

Для JWT добавьте в `backend/.env` уникальный секрет. Его можно сгенерировать командой:

```powershell
.\.venv\Scripts\python.exe -c "import secrets; print(secrets.token_urlsafe(48))"
```

Скопируйте результат в `.env`:

```env
JWT_SECRET_KEY=вставьте_сгенерированную_строку
JWT_ALGORITHM=HS256
ACCESS_TOKEN_EXPIRE_MINUTES=15
REFRESH_TOKEN_EXPIRE_DAYS=7
```

При необходимости измените `CORS_ORIGINS`. По умолчанию разрешены адреса Vite: `http://localhost:5173` и `http://127.0.0.1:5173`.

### 3. Запустите API

Находясь в `backend`, выполните:

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload
```

API будет доступен по адресу `http://127.0.0.1:8000`.

После первого запуска FastAPI создаст таблицы `mentors`, `students`, `appointments`, `notes`, `users` и `refresh_sessions` в подключённой базе данных.

Полезные адреса:

- `http://127.0.0.1:8000/health` — проверка работоспособности;
- `http://127.0.0.1:8000/docs` — Swagger UI;
- `http://127.0.0.1:8000/redoc` — альтернативная документация.

### 4. Проверьте API через Swagger UI

Откройте `http://127.0.0.1:8000/docs`. Для проверки аутентификации сначала вызовите `POST /api/v1/auth/register` или `POST /api/v1/auth/login`. Скопируйте `access_token` в кнопку **Authorize** и укажите формат `Bearer <access_token>`. После этого можно проверять закрытые маршруты профиля, встреч и заметок.

После запуска обновите в pgAdmin список таблиц: в схеме `public` должны появиться `mentors`, `students`, `appointments`, `notes`, `users` и `refresh_sessions`.

## Основные API-маршруты

Все маршруты API начинаются с `/api/v1`.

| Сущность | Маршрут | Операции |
| --- | --- | --- |
| Наставники | `/api/v1/mentors` | создание, список, получение, изменение, удаление |
| Ученики | `/api/v1/students` | создание, список, получение, изменение, удаление |
| Встречи | `/api/v1/appointments` | создание, список, получение, изменение, удаление |
| Заметки | `/api/v1/notes` | создание, список, получение, изменение, удаление |
| Аутентификация | `/api/v1/auth/register`, `/login`, `/refresh`, `/logout`, `/me` | регистрация, вход, обновление access token, выход, текущий пользователь |

Подробное описание модели данных, бизнес-правил, форматов запросов и результатов проверки находится в [REPORT_LAB_2.md](REPORT_LAB_2.md).

В корне репозитория:

```powershell
npm install
npm run dev
```

Если PowerShell блокирует `npm.ps1`, используйте `npm.cmd install` и `npm.cmd run dev`.

Frontend использует API FastAPI для регистрации, входа, восстановления сессии и выхода. Данные наставников, встреч и заметок пока остаются демонстрационными; полная интеграция этих экранов с API будет выполнена в лабораторной работе №5.
